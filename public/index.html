Backup na nuvem

    

      
Google Drive em um clique

      
Instala o rclone sozinho (se faltar), abre o navegador para você autorizar o Google Drive e já deixa o envio automático ligado depois de cada backup agendado. O acesso é só aos arquivos que o próprio RDR Local cria, nunca ao seu Drive inteiro.

      

        
        
      

      
Avançado: nome do destino e Client ID próprio
        

          
          
          
          
Sem Client ID próprio o Google limita a velocidade e, se o app OAuth ficar em modo "Teste", a autorização expira em 7 dias. O passo a passo está no guia Backup na nuvem, na Ajuda.

        

      

      

      

      
Depois de conectar: Enviar agora e Testar restauração (mais abaixo). A senha de criptografia não é guardada em texto: anote-a, sem ela o backup é irrecuperável.

    

    

      
1. Ferramenta de envio (rclone)

      
O RDR Local usa o rclone (open source) para enviar os backups ao Google Drive, Dropbox, S3/R2/B2 ou a uma pasta. O download é conferido por SHA-256.

      

    

    

      
2. Destinos

      

      
As credenciais ficam em , com acesso restrito ao seu usuário. Elas não entram na exportação de configuração.

    

    

      
3. O que e como enviar

      

        
        
        
        
        
        
      

      

      
Criptografia (recomendada)

      
Cifra nomes e conteúdo antes de sair do seu PC: quem tiver acesso ao Drive não lê seus bancos. Se perder a senha, não há como recuperar o backup. Guarde-a em um gerenciador de senhas. Ela não é salva em texto.

GitHub

    

      
1. Git

      
O Git é usado para clonar e atualizar seus projetos. Se você já tem o Git no Windows, o RDR Local usa o seu; senão, instale o Git portátil (MinGit) aqui.

      

    

    

      
2. Conta

      

        
Opção A (recomendada): login pelo navegador. Crie um OAuth App em github.com/settings/developers, marque Enable Device Flow e cole o Client ID abaixo. Nenhuma senha passa por aqui. Detalhes no guia “GitHub” da Ajuda.

        

        

        
Opção B: token pessoal fine-grained com Contents: Read e Metadata: Read apenas nos repositórios que quiser usar.

        

      

      
Conectado como 

      
O token fica cifrado com o Windows (DPAPI), só para o seu usuário, e é enviado apenas a github.com. Ele não aparece em .git/config nem em URLs. Desconectar apaga daqui; para revogar de vez, apague o token no GitHub.

    

    

      
3. Seus repositórios

      
Conecte sua conta para listar.

    

    

      
4. Sites com Git

      

      
“Atualizar” só faz git pull --ff-only e recusa se houver arquivo alterado sem commit. O RDR Local não faz commit, push nem deploy.

    

  


  
  

    
Publicar

    

    

      
Servidores

      

    

    

      
Receitas de publicação

      
Uma receita é a lista de comandos que roda no servidor (ex.: atualizar os serviços do Docker Swarm). O painel só executa o que está numa receita sua: não há terminal livre. Antes de publicar ele confere se o código está no GitHub e se o build terminou.

      

    

    

      
Sites antigos (FTP / FTPS / SFTP)

      
Envia só o que mudou desde a última publicação. Mostra a prévia antes, nunca envia .env e só apaga no servidor se você confirmar.

      

      

    

    

      
Chaves SSH

      

      
A chave privada fica cifrada com o Windows (DPAPI) e nunca é mostrada. Só a chave pública aparece, para você colocar no authorized_keys do servidor.

Certificado SSL

    

      
O RDR Local cria uma autoridade certificadora (CA) própria e emite um certificado para cada site. Ao confiar na CA no Windows, o navegador mostra o cadeado verde sem avisos.

Portas

      

      
Bancos usam portas diferentes das padrão (3307, 5433, 6380) para conviver com ServBay/XAMPP. Web em 80/443 dá URLs limpas — se outro programa usa essas portas, pare-o ou troque aqui (a URL passa a incluir a porta).

      
      
Conectar agentes de IA (MCP)

      
Deixa o Claude, Cursor, Codex e similares consultarem e controlarem o RDR Local: ver serviços e logs, rodar o Diagnóstico, ligar/desligar serviços, backup, migrate. Nada destrutivo é exposto (sem excluir banco ou site). O RDR Local precisa estar aberto.

      

      
O “terminal liberado” deixa o agente executar comandos na pasta dos seus projetos — só use com agentes em que você confia.

      
Exportar / importar configuração

      
Leva seus sites, portas e preferências para outro PC (ou guarda um backup deles). Não inclui bancos de dados nem arquivos dos projetos. Ao importar, sites que já existem são mantidos.

Restaurar banco

    

      
      
      
    

    
Se o banco de destino já existir, o RDR Local faz um backup dele, apaga e recria a partir do arquivo.

    

  





  
PHP

  

  

  

  

    

  
Ao salvar, o RDR Local testa o php.ini; se o PHP reclamar, a alteração é desfeita. Os workers do PHP reiniciam sozinhos.

  




  

    
Clonar repositório

    

      
      
      
      
      
    

    
Se tiver composer.json, roda composer install, cria o .env e gera a APP_KEY. As migrations não são executadas.

    

  



  

    
Importar sites de outro ambiente

    
Lê só a configuração do ServBay, Laragon ou XAMPP (nada é alterado lá) e cria sites aqui apontando para as mesmas pastas. Bancos de dados não são movidos: use backup e restauração na aba Bancos.

    

    

    

    

  



  

    
Importar bancos de outro servidor

    
Copia bancos MySQL/MariaDB de um servidor ligado neste PC (ServBay, Laragon, XAMPP) para o MariaDB do RDR Local e confere tabelas e linhas. A origem só é lida. O arquivo .sql fica guardado em Backups.
